# Промпты для Claude Code: сканер выгодных объявлений (Bazoš + FB → Gemini → Telegram)

## Перед стартом (5 минут)
1. **Telegram-бот:** @BotFather → `/newbot` → сохрани токен. Напиши своему боту `/start`, потом открой `https://api.telegram.org/bot<TOKEN>/getUpdates` и найди свой `chat.id`.
2. **Gemini API-ключ:** aistudio.google.com → Get API key. Бесплатного тарифа хватает: Gemini вызывается только для отобранных кандидатов, это десятки запросов в день.
3. Создай пустой репозиторий (например `deal-scanner`) и положи в него папку `knowledge/` из этого архива (`prices.json`, `KNOWLEDGE.md`) и этот файл.
4. Открой папку в Claude Code. Вставляй промпты **по одному**. После каждого проверь, что работает, и сделай коммит.

Совет: перед каждым промптом включай Plan mode (Shift+Tab), чтобы Claude Code сначала показал план, а ты его подтвердил.

## Промпт 1 — каркас + парсер Bazoš

```
Мы строим личный сканер выгодных объявлений для перепродажи б/у электроники в Чехии.
Прочитай knowledge/KNOWLEDGE.md и knowledge/prices.json — это моя база знаний и прайс. Там же описано,
как устроены страницы Bazoš (селекторы, URL, пагинация) — я проверял это вручную.

Задача этого шага:
1. Python 3.12 проект: pyproject или requirements.txt, структура пакета scanner/,
   конфиг через .env (pydantic-settings) + config.yaml для поисковых запросов.
   Создай .env.example (TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, GEMINI_API_KEY, GEMINI_MODEL).
   .env в .gitignore.
2. CLAUDE.md с кратким описанием проекта, архитектуры и правил (код и комментарии на английском,
   общение со мной на русском, тексты продавцам на чешском).
3. Модуль scanner/sources/bazos.py: httpx + selectolax (или BeautifulSoup).
   - Поиски из config.yaml: рубрика mobil: iphone, apple watch, airpods, ipad;
     рубрика pc: macbook, playstation, xbox, nintendo switch, "herní pc", rtx, + категория /graficka/.
   - Для каждого поиска: hlokalita=56201, humkreis=60, свои cenaod/cenado, первые 2 страницы.
   - Нормализованная модель Listing: source, id, url (полный, со slug), title, price (int|None),
     location, posted_date, description (None пока), first_seen, last_seen.
   - Вежливость: случайная пауза 2–5 с между запросами, нормальный User-Agent, таймауты, ретраи
     с бэкоффом, никаких параллельных запросов к Bazoš.
   - fetch_detail(url): h1, цена через "Cena:", описание .popisdetail.
4. SQLite (scanner/db.py): таблица listings (уникально по source+id), история цен (price_history),
   поле status (new/alerted/hidden/contacted). Функция upsert, которая возвращает: новое объявление
   / цена изменилась / без изменений.
5. CLI: `python -m scanner run-once --dry` — прогон всех поисков Bazoš, вывод новых объявлений
   таблицей в консоль. Никакого Telegram и Gemini на этом шаге.
6. Тесты pytest для парсера на сохранённых HTML-фикстурах (сохрани 2 реальные страницы выдачи
   и 1 деталь в tests/fixtures при первом запуске).

Запусти run-once --dry и покажи мне результат. Если селекторы не совпадают с реальным HTML —
исправь и обнови раздел в KNOWLEDGE.md.
```

## Промпт 2 — оценка по прайсу (без ИИ)

```
Теперь движок оценки scanner/pricing.py, полностью на правилах, без LLM.

1. Загрузка knowledge/prices.json. Для каждого Listing определить, какой позиции прайса он соответствует:
   категория + модель + вариант (память/размер). Сделай нормализацию заголовка (регистр, диакритика,
   "16pro"→"16 pro", "gb/GB/ГБ", "TB"), словарь синонимов и regex для моделей iPhone 11–17
   (base/Plus/Pro/Pro Max/mini/e), Apple Watch (Series N, SE, Ultra 1/2/3, размер мм),
   AirPods, iPad, MacBook (Air/Pro, чип M1–M5, Pro/Max, диагональ, RAM/SSD), PS4/PS5 (Slim/Pro/Digital),
   Xbox Series S/X/One, Switch (V1/V2/OLED/Lite/2), видеокарт (RTX/RX + VRAM).
   Если память не указана — бери минимальный вариант модели и пометь match_confidence=low.
2. Посчитать: market_price, target_buy = round(market*buy_pct/100, -2) (buy_pct из config, по умолчанию 72;
   для liquidity=1 — 68), discount_pct = 1 - price/market, expected_profit = market - price.
3. Предфильтр «кандидат»: есть совпадение с прайсом И price <= market*0.90 И price >= market*0.40
   (ниже 40 % — почти всегда развод или битое, такие помечай отдельным флагом "too_cheap").
   Плюс отдельные стоп-слова из KNOWLEDGE.md: koupím, výměna, na díly, blokovaný, iCloud, prodáno, obal, kryt, sklo
   (аксессуары не путать с устройствами).
4. Шаблоны мошенников из KNOWLEDGE.md закодируй как правила (город+категория+диапазон цены,
   "pošlete zprávu na e-mail" и т.п.) → флаг scam_suspect.
5. Score 0–100: скидка к рынку, ликвидность, ожидаемая прибыль в Kč, расстояние (город из списка
   ближних — бонус), свежесть. Ранжировать кандидатов.
6. CLI `python -m scanner run-once --dry` теперь показывает только кандидатов с оценкой.
7. Тесты на матчинг: минимум 30 реальных заголовков (возьми из выдачи шага 1) с ожидаемым результатом.

Покажи мне топ-10 кандидатов с текущего прогона.
```

## Промпт 3 — Gemini как «второе мнение»

```
Подключи Gemini через официальный SDK google-genai. Модель берётся из env GEMINI_MODEL.
Сначала проверь в документации Google AI Studio, какие модели сейчас доступны на бесплатном тарифе
и какие у них лимиты (RPM/RPD), и поставь по умолчанию самую дешёвую быструю модель из семейства Flash.

Gemini вызывается ТОЛЬКО для кандидатов из pricing.py (не для всех объявлений) и только один раз
на объявление (кэш в SQLite по source+id+price). Перед вызовом подгрузи описание через fetch_detail.

Вход в промпт Gemini: KNOWLEDGE.md (как системная инструкция), найденная позиция прайса
(market, target_buy, liquidity, confidence), данные объявления (заголовок, цена, город, дата, описание).

Выход — строго JSON по схеме (response_schema):
{
  "is_device": bool,               // не аксессуар/не "koupím"
  "model": str, "variant": str,    // что это на самом деле по описанию
  "matches_price_item": bool,      // правильно ли pricing.py сопоставил позицию
  "condition_notes": [str],        // батарея %, ремонт, трещины, комплект, гарантия
  "adjusted_market_price": int,    // рынок с поправкой на состояние по правилам из KNOWLEDGE.md
  "red_flags": [str],
  "scam_risk": "low|medium|high",
  "verdict": "buy|negotiate|skip",
  "offer_price": int,              // что предложить первым сообщением
  "max_price": int,                // выше не брать
  "reason_ru": str,                // 1–2 предложения по-русски
  "message_cs": str                // готовое первое сообщение продавцу на чешском, на "vy", коротко
}

Требования:
- Rate limiter под лимиты бесплатного тарифа, ретраи на 429 с бэкоффом.
- Если Gemini недоступен или кончился лимит — не падать: отправлять уведомление только с оценкой
  по правилам и пометкой «без ИИ».
- Пересчитывай итоговую прибыль по adjusted_market_price. Если verdict=skip или scam_risk=high —
  в Telegram не отправлять (но сохранять в БД, чтобы можно было посмотреть командой).
- Логируй токены/запросы за день.

Прогони на 5 текущих кандидатах и покажи мне JSON-ответы.
```

## Промпт 4 — Telegram-бот + расписание каждые 10 минут

```
Сделай Telegram-бота на aiogram 3 и планировщик (APScheduler, один процесс, asyncio).

Планировщик:
- Bazoš — каждые 10 минут (+ случайный джиттер 0–90 с). Пропускать прогон, если предыдущий ещё идёт.
- Тихие часы 00:30–06:30: сканировать раз в 30 минут, уведомления копить и прислать утром одной сводкой.

Уведомление о кандидате (HTML parse mode), пример:
🟢 iPhone 16 Pro 128 GB — 15 500 Kč  (Bazoš, Hradec Králové, сегодня)
Рынок ~16 500 · цель ≤ 11 900 · предложить 14 000 · максимум 15 000
Прибыль ~1 500–2 500 · ликвидность ●●●
🔋 89 % · без ремонта · iCloud вышел
⚠️ флаги: —
💬 [готовое сообщение на чешском в <code>, чтобы копировалось нажатием]
🔗 ссылка
Эмодзи: 🟢 buy, 🟡 negotiate. Цветом не злоупотреблять.

Кнопки под сообщением: «✍️ Написал» (status=contacted), «🙈 Скрыть», «🔁 Снизится — сообщи»
(следить за этим объявлением и прислать, если цена упадёт ≥5 %).

Отдельные события:
- Снижение цены у уже виденного объявления, которое теперь проходит фильтр → новое уведомление «📉».
- Объявление, на которое я нажал «Написал», пропало/продано → короткое сообщение.

Команды:
/status — когда был последний прогон, сколько объявлений, ошибки, лимиты Gemini.
/pause, /resume
/top — 10 лучших активных кандидатов за 24 ч.
/skipped — что Gemini отбраковал за 24 ч (с причинами), чтобы я мог проверить, не врёт ли он.
/pct 72 — поменять процент покупки.
/radius 60 — поменять радиус для Bazoš.
/price <позиция> <цена> — поправить market_price в prices.json (поиск позиции по подстроке,
   если найдено несколько — кнопки выбора), с логом изменений.
/search add|remove|list — управление поисковыми запросами без правки кода.

Бот отвечает ТОЛЬКО на TELEGRAM_CHAT_ID (мой), остальных игнорирует.
Точка входа: `python -m scanner bot`. Проверь end-to-end: прогон → сообщение в мой чат.
```

## Промпт 5 — Facebook Marketplace (отдельно и осторожно)

```
Добавь источник scanner/sources/facebook.py на Playwright (Chromium) — по описанию в KNOWLEDGE.md.

- У FB нет публичного API для Marketplace, автоматизация нарушает их правила, и аккаунт могут
  временно ограничить. Поэтому: источник выключен по умолчанию (FB_ENABLED=false), интервал

  массовых открытий карточек (детали — только для кандидатов, не больше 10 за прогон).

  profile (папка fb_profile/ в .gitignore), я логинюсь руками, профиль сохраняется. Никаких паролей в коде/.env.
- Если FB показал стену логина / checkpoint / капчу — НЕ пытаться обходить: остановить FB-источник,
  прислать мне в Telegram «FB требует входа, запусти fb-login», ждать.
- Локация и радиус берутся из настроек аккаунта (у меня Ústí nad Orlicí, 60 км), плюс фильтр
  по списку ближних городов из KNOWLEDGE.md на стороне парсера (FB иногда подмешивает всю страну).
- Парсер не должен зависеть от языка интерфейса (у меня русский): цену ищи по "CZK|Kč",
  пропускай строки "Недавно опубликовано"/"Just listed".
- Те же поиски, что для Bazoš, параметр daysSinceListed=1.
- Результаты идут в тот же pipeline (pricing → Gemini → Telegram), source="fb".

Сначала сделай fb-login и один ручной прогон `python -m scanner run-once --source fb --dry`,
```

## Промпт 6 — самообучающийся прайс

```
Сделай так, чтобы прайс не устаревал.

1. Все объявления, которые pricing.py уверенно сопоставил (match_confidence=high, не scam, не too_cheap),
   записывай как наблюдения цены (asking price) по позиции прайса с датой и источником.
2. Если объявление исчезло через N дней — считай это вероятной продажей и сохраняй «цену ухода»
   (последнюю цену). Это сигнал сильнее, чем цена объявления.
3. Раз в неделю (воскресенье 19:00) присылай отчёт: по каждой позиции с ≥5 наблюдениями —
   медиана asking, медиана «ушло за», текущий market_price, предлагаемое новое значение
   (консервативно: не больше ±8 % за неделю). Кнопки «Применить всё» / «Применить выборочно».
   Ничего не менять без моего подтверждения.
4. Позиции с confidence=estimate выделяй в отчёте первыми — их надо уточнить.
5. Новые модели, которые часто встречаются, но которых нет в прайсе (например новые iPhone),
   предлагай добавить.
```
